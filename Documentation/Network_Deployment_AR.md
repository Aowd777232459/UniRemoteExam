# تشغيل النظام والمزامنة عبر الشبكة

## التصميم المعتمد

يعمل النظام بخادم مركزي واحد وقاعدة SQL Server مركزية واحدة. تطبيق أندرويد وتطبيق ويندوز يعرضان واجهات الخادم الآمنة نفسها، لذلك لا توجد نسختان منفصلتان من البيانات تحتاجان إلى دمج يدوي. أي عملية يحفظها مستخدم من الجوال تصبح متاحة للكمبيوتر فور اكتمال الحفظ واتصال الجهازين بالخادم.

## ما يلزم للتشغيل الحقيقي عبر الإنترنت

1. خادم Windows أو Linux يدعم .NET 10.
2. SQL Server 2019 أو أحدث، ويفضل أن يكون داخل شبكة خاصة مع الخادم.
3. اسم نطاق، مثل `exam.example.com`.
4. شهادة HTTPS صالحة. تطبيقات الأجهزة ترفض الروابط غير الآمنة عمدًا لحماية كلمات المرور وبيانات الطلاب.
5. نسخة احتياطية يومية مشفرة من قاعدة البيانات.

## إعداد قاعدة البيانات

نفّذ `Database/CREATE_DATABASE_FULL.sql` على SQL Server مرة واحدة. لا تنفذ ملفات إعادة الضبط على بيانات حقيقية.

## إعداد أسرار الخادم

لا تضع كلمة مرور قاعدة البيانات أو البريد داخل GitHub. اضبطها على الخادم بمتغيرات البيئة:

```text
ConnectionStrings__DefaultConnection
Smtp__Username
Smtp__Password
AllowedHosts
```

يمكن استخدام `appsettings.Production.example.json` قالبًا، لكن يجب حفظ الملف الحقيقي خارج GitHub.

## فحص الجاهزية

بعد النشر افتح:

```text
https://YOUR-DOMAIN/health
```

الحالة `200` مع `database: connected` تعني أن الخادم وقاعدة البيانات جاهزان. الحالة `503` تعني أن التطبيق يعمل لكن قاعدة البيانات غير متاحة.

## ربط تطبيقات الأجهزة

عند فتح تطبيق أندرويد أو ويندوز لأول مرة، أدخل رابط الخادم الذي يبدأ بـ `https://`. يحفظ التطبيق الرابط على الجهاز، ويفحص الخادم وقاعدة البيانات قبل فتح شاشة الدخول.

## سلوك انقطاع الشبكة

- البيانات التي اكتمل حفظها تبقى في قاعدة البيانات المركزية.
- لا يخزن التطبيق صفحات الاختبارات أو النتائج القديمة للاستخدام دون اتصال حتى لا يعرض بيانات غير محدثة.
- عند عودة الإنترنت يعيد التطبيق فحص الخادم ويمكن متابعة العمل.
- الحفظ الذي ينقطع قبل وصول تأكيد الخادم يجب إعادة تنفيذه؛ لا يفترض التطبيق نجاحه دون تأكيد.
